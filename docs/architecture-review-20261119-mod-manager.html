Problem

scripts/preload.nut hardcodes CampaignCarryover via irreversible one-way method assignments while g_*_defs mutates global tables once at boot with no hook stack or mod discovery index.

Solution

Extract a deep ModCatalog module at the scripts/preload.nut seam that manages mod manifests, reversible method-hook chains, g_*_defs base snapshots, and scripts/mods/*.nut loading.

Wins

  • Locality: hook rollback lives in one module
  • Leverage: every mod shares one seam
  • CampaignCarryover becomes a first-class mod
  • Two adapters test mod CRUD offline

Problem

MainSubMenu and Starting Camp HUDInGameMenuManager use incompatible widget layouts and hardcoded event slots (m_ingame_menu = 3, InputEvent(5) 101..103, menu_event = 5) that collide when a second mod adds UI.

Solution

Create one deep ModBrowserUI module that allocates collision-free menu and InputEvent IDs, auto-links weakref() focus chains, and renders the Mod Manager in Main Menu, Pause Menu, and Starting Camp.

Wins

  • Locality: focus and event IDs in one place
  • Leverage: one UI module, three menu mounts
  • Zero event ID collisions across user mods
  • Tests verify UI flows without OpenGL

Problem

Mods cannot add StateObject fields without breaking ADR-0001 binary compatibility, and disabling a mod mid-run leaves orphaned item keys in Mid-Run Save blobs that crash Hero.initialize_from_hero_data().

Solution

Provide a deep ModdedPersistence module that piggybacks namespaced mod key-values inside ProfileData hero strings, sanitizes missing mod defs on resume, and stores mod settings via File.

Wins

  • Locality: serialization guards in one module
  • Preserves ADR-0001 StateObject layout
  • Disabling a mod never bricks Continue
  • Mods get run-scoped persistence for free

Solution

Deepen SquirrelVM with try/catch, compilestring(), and a standard host environment adapter (System.run_script, File, ProfileData), and whitelist scripts/mods/** in .gitignore.

Wins
